# hazchem-store — 危化品批次最少库位规划 API

纯 Go 1.23 `net/http` 后端 JSON API（无第三方依赖），把一批危化品批次**恰好**分配到若干库位房间：

- 同一房间内的批次不得存在互斥（互斥图中的相邻顶点必须异色）；
- 每个房间入住批次数不超过 `capacity`；
- 首先**最小化房间数**（精确搜索，不是贪心“顺手放下一批”）；
- 房间数相同的多个最优解之间，按批次 id 的 **UTF-8 字节序**排列批次，
  房间按“首次出现的批次”依次编号为 0、1、2……，取**编号向量字典序最小**的规范方案。

## 运行

```bash
docker compose up --build
# 服务监听 :8080
```

本地直接运行 / 测试：

```bash
go test ./...        # 求解器对拍 + HTTP 层测试
go run .             # 默认 :8080，可用 PORT 覆盖
```

## 请求

`POST /plan`，`Content-Type: application/json`：

```json
{
  "batches": ["A01", "A02", "B01", "B02"],
  "capacity": 2,
  "exclusions": [["A01", "B01"], ["A02", "B02"], ["B01", "B02"]]
}
```

| 字段 | 规则 |
| --- | --- |
| `batches` | 2–14 个**唯一** id；1–64 个可打印 ASCII 字符（0x21–0x7E，无空格） |
| `capacity` | 整数 1–14 |
| `exclusions` | 无向互斥对数组；每对恰好两个字符串 id |

任何语义问题整次请求返回 **422**：重复/反向重复的无向边、自互斥（`["x","x"]`）、
引用未知 id、未知/额外字段、类型错误（如 `capacity: 2.5`、id 用数字）、
数量越界、id 重复或含非 ASCII/空白字符。JSON 语法损坏或空请求体返回 **400**。

## 响应（200）

```json
{
  "batches": ["A01", "A02", "B01", "B02"],
  "room_count": 2,
  "numbering_vector": [0, 1, 1, 0],
  "rooms": [
    {"room": 0, "batches": ["A01", "B02"], "occupancy": 2},
    {"room": 1, "batches": ["A02", "B01"], "occupancy": 2}
  ]
}
```

- `batches`：按 UTF-8 字节序排序，是 `numbering_vector` 的下标顺序；
- `numbering_vector[i]`：第 `i` 个批次所在房间号；
- `rooms`：房间 0..room_count-1，每间给出批次清单（字节序）与 `occupancy`。

库管员可用 `numbering_vector` + `rooms` 独立复算：房间数为最优值、每间不超容量、
无互斥对同房。

### 为什么不能贪心

`capacity=2`、互斥边 `ac / bd / cd` 时，“下一批放进第一个可用房间”会开出 3 间，
而精确最优是 2 间：`{a,d} | {b,c}`。该用例在 `storage/solver_test.go` 的
`TestGreedyIsSuboptimal` 中固化，HTTP 层也有对应用例断言 `room_count=2`。

## 求解器

`storage` 包：

- **消除房间标签对称性**：顶点按 id 字节序处理，顶点 i 的房间号只能取
  `0..1+max(a[0..i-1])`（受限增长串），每个无标签划分恰好枚举一次；
  另对“规模 + 对未着色顶点冲突集”相同的等价房间去重。
- **精确搜索**：自下界（`ceil(n/capacity)` 与互斥图最大团数取大）起逐 k 回溯，
  第一个可行 k 即被证明为最少房间数；同一 k 内按标签升序尝试，第一个解即
  编号向量字典序最小者。含前向检查剪枝。
- n ≤ 14 时为位运算回溯；实测 300 个 n=14 随机难例最坏耗时约 42µs。

测试中 `bruteOptimal` 是独立的规范划分全枚举参考实现：小批次（n≤5 时枚举
**全部**图 × 全部容量；n=6..9 随机抽样）对拍，覆盖完全互斥（K_n 每批独占一间）、
空互斥（按容量打包）和多解并列的字典序裁决。
