# 危化品批次库位分配服务

纯 `net/http` 后端 JSON API（Go 1.23，无第三方依赖）：把一批互斥关系约束下的危化品批次**恰好**分入若干库位，同室批次不得互斥且不超容量，**先最小化库位数**，多解时取规范编号向量字典序最小的方案。结果是精确搜索得到的最优解，不是贪心近似。

## 运行

```bash
docker compose up --build        # 服务监听 :8080
# 或本地：
go run ./cmd/api                 # PORT 环境变量可改端口，默认 8080
```

## 测试

```bash
go test ./...
```

求解器测试包含：完全互斥、空互斥、多解并列 tie-break、贪心会次优的冠图实例；并对 4、5 个批次的**全部**互斥图 × 全部容量枚举所有规范分组（restricted growth string）对拍，以及 2–8 批次随机实例对拍、14 批次大实例的合法性与可复算性校验。

## API

### `POST /allocate`

请求：

```json
{
  "batches": ["c", "a", "b"],
  "capacity": 2,
  "exclusions": [["a", "c"]]
}
```

- `batches`：2–14 个**唯一**、非空、纯 ASCII 的批次 id。
- `capacity`：每室最多容纳批次数，1–14。
- `exclusions`：互斥批次对（无向）。可省略。

响应（200）：

```json
{
  "batches": ["a", "b", "c"],
  "roomCount": 2,
  "vector": [0, 0, 1],
  "rooms": [["a", "b"], ["c"]],
  "occupancy": [2, 1]
}
```

- `batches`：按 UTF-8 字节序排序后的批次 id，`vector` 与此顺序对齐。
- `vector`：`vector[i]` = 批次 `batches[i]` 所在房间号。房间按“首次出现的批次”依次编号 0、1、2……（规范形式，消除房间标签对称性）。
- `rooms` / `occupancy`：每个房间内的批次（已排序）与占用数。
- 方案保证：使用房间数最少；并列时编号向量字典序最小。结果确定，可复算。

### 错误码

| 状态码 | 情形 |
|---|---|
| 400 | JSON 语法错误、字段类型错误、请求体后有多余数据 |
| 405 | 方法非 POST |
| 422 | 语义校验失败（整次拒绝）：批次数量不在 2–14、id 为空/非 ASCII/重复、capacity 不在 1–14、**重复的无向互斥边**（`["a","b"]` 与 `["b","a"]` 视为同一条）、**自己互斥**、**未知 id**、**额外字段**、互斥对长度不为 2 |

错误响应形如 `{"error": "..."}`。

### `GET /healthz`

返回 `{"status":"ok"}`。

## 算法说明

1. 批次 id 按 UTF-8 字节序排序，映射为下标 0..n-1；互斥关系存为位掩码邻接。
2. **消除房间标签对称性**：只搜索规范编号向量（restricted growth string）——第 i 个批次只能进入已开房间或“下一个新房间”，等价于房间按首次出现编号。
3. **下界**：房间数下界 = max(⌈n/capacity⌉, 互斥图最大团大小)（Bron–Kerbosch 位运算求最大团）。
4. **精确搜索**：从下界起逐个 k 做深度优先可行性搜索；同一 k 内按房间号升序尝试，第一个完整解即该 k 下字典序最小向量；容量剩余槽位剪枝。第一个可行的 k 即最少房间数，其解即全局最优且字典序最小。

由于输入被规范化为排序下标且搜索确定，同一实例无论何时请求都得到同一方案。
